详细审查发现

P0 — 严重缺陷

  1. [P0-1] G9N9NProtocol 误将无 Report ID 的 Power 键报文（0x01）当作 Report ID 1 剥离
    • 源码：src/RemoteBuddy.Core/Protocols/G9N9NProtocol.cs（TryParseReport / TryParseReport1，L35–54、L63–101、L159–163）
    • 根因与影响：IndexedConsumerUsages 中索引 1（0x01）对应 RemoteButton.Power，但 TryParseReport1 在 slice.Length == 2 && slice[0] == 1 时无条件执行 slice = slice[1..]。WinRT BLE GATT HID Input Report 通知默认不携带前导 Report ID，按下 Power 键收到 [0x01, 0x00] 时首字节被剥离，返回空按键列表——电源键按下被静默吞掉并误判为松开；组合键 Power + Up（[0x01, 0x03]）误解析为仅 Up。
    • 修复方案：增加显式 bool? hasReportId = null 参数由传输层传入；启发式模式下仅当 slice.Length >= 3 && slice[0] == 1 时剥离 Report ID 1。
  2. [P0-2] T1RemoteProtocol.IsCandidate 对 "t1" 执行宽松子串匹配且优先级最高，导致大量蓝牙设备误识别为 T1Remote
    • 源码：src/RemoteBuddy.Core/Protocols/T1RemoteProtocol.cs（L25–46）、src/RemoteBuddy.Core/Protocols/G9N9NProtocol.cs（XiaomiProtocol.DetectModelType，L297–309）
    • 根因与影响：L37 虽检查了精确匹配 clean == "t1" || clean.Contains("t1 remote")，但 L41–44 紧接着遍历含 "t1" 的 CandidateNames 执行 name.Contains(...)，彻底击穿保护。任何名称含 "t1" 的设备（如 "BT100"、"Headset1"、"Mi Remote BT1"）都会被最高优先级误识别为 RemoteModelType.T1Remote，加载错误映射与解码器。
    • 修复方案：移除 CandidateNames 中的 "t1" 子串匹配，仅保留精确相等 "t1" 或完整词组 "t1 remote"。

P1 — 高危隐患

  1. [P1-1] ATVVFrameAccumulator 缺乏线程同步，BLE 音频与控制通道并发回调存在竞态
    • 源码：src/RemoteBuddy.Core/Protocols/ATVVProtocol.cs（ATVVFrameAccumulator，L159–304）
    • 根因与影响：WinRT BLE 的 AudioUuid（AB5E0003）与 ControlUuid（AB5E0004）ValueChanged 回调可并发运行在不同线程池线程上，对 _buffer、_pendingSync、_framesBeforeSync 无锁访问会导致 _pendingSync 撕裂读、ADPCM 预测器错帧重置（爆音/啸叫）或 IndexOutOfRangeException。
    • 修复方案：引入锁保护并原子递交帧与同步状态（避免持锁执行外部长耗时回调）。
  2. [P1-2] T1RemoteProtocol.DecodeReport 无 Report ID 头部剥离未结合长度校验，带修饰键的键盘报文解析错乱
    • 源码：src/RemoteBuddy.Core/Protocols/T1RemoteProtocol.cs（DecodeReport，L65–95）
    • 根因与影响：仅凭 data[0] 属于 {1, 2, 3, 4, 0x5A} 就剥离首字节。8 字节无 Report ID 标准键盘报文按住 Left Ctrl (0x01)、Left Shift (0x02)、Ctrl+Shift (0x03) 或 Left Alt (0x04) 时会被分别判为无效、误入 Consumer/SystemControl 分支或被 Mouse 分支静默忽略。
    • 修复方案：支持显式 byte? reportId，启发式模式必须同时校验 (data[0], data.Length) 组合（如 9 字节键盘、3 字节 Consumer、2 字节 SystemControl）。
  3. [P1-3] G9N9NProtocol.TryParseReport2 未校验 Report ID 2 的奇数长度，偶数字节无 Report ID 报文错位
    • 源码：src/RemoteBuddy.Core/Protocols/G9N9NProtocol.cs（TryParseReport / TryParseReport2，L103–132、L165–169）
    • 根因与影响：Report 2 为 16 位 Consumer Usage，带 1 字节 Report ID 0x02 时总长必为奇数。未校验 Length % 2 == 1 会导致 4 字节无 Report ID 报文首字节为 0x02 时被误剥离并整体错位 1 字节。
    • 修复方案：收紧条件为 slice.Length >= 3 && slice.Length % 2 == 1 && slice[0] == 2 并支持显式 hasReportId。
  4. [P1-4] G9N9NSmartToggleSession 存在非法状态跃迁、TOCTOU 竞态与非单调时钟回退风险
    • 源码：src/RemoteBuddy.Core/Protocols/G9N9NSmartToggleSession.cs（L70–108）
    • 根因与影响：EnterAwaitingReopen() 无前置状态校验，可从 Idle/Closing/HandsFreeActive 强行跃迁；ShouldReopenOnPhysicalStop 与 EnterAwaitingReopen 分两次加锁存在 TOCTOU；时间差仅判 < HoldThresholdMs，若发生时钟回拨（差值为负）会误判长按为短按进入免提模式。
    • 修复方案：合并为原子方法 TryEnterAwaitingReopen，在锁内校验 PhysicalPressed、代际号及 elapsed >= 0 && elapsed < HoldThresholdMs。
  5. [P1-5] RemoteButtonGestures 缺少定时器取消防重入守卫，迟发回调可引发 60 秒幽灵连发
    • 源码：src/RemoteBuddy.Core/Models/RemoteButtonGestures.cs（Schedule/Repeat/HandleDown，L41–45、L62–69、L81–125）
    • 根因与影响：Schedule 闭包无 cancelled 标志，Repeat() 未校验 press.IsDown 与当前实例身份；已入队回调在按键松开后仍会执行并自我重调度，持续触发至 MaximumRepeatMilliseconds（60 秒）；HandleDown 先 Fire() 后置位 FiredOnPress，异常时 HandleUp 会二次触发。
    • 修复方案：在 Schedule 闭包内加 bool cancelled 守卫，Repeat 校验 press.IsDown 与实例匹配，HandleDown 先置位 FiredOnPress = true 再执行动作。
  6. [P1-6] ConfigService.Current 暴露无锁可变对象图，且 SaveLocked 缺刷盘保证并静默吞错
    • 源码：src/RemoteBuddy.Core/Config/ConfigService.cs（L24、L294–403）
    • 根因与影响：Current 暴露可变集合，跨线程修改与 CreateSnapshot 并发可抛 InvalidOperationException；File.WriteAllText 未 Flush(flushToDisk: true)，异常断电可写落空文件；SaveLocked 捕获异常后不返回状态，调用方无法感知保存失败。
    • 修复方案：使用 FileStream + FileOptions.WriteThrough + Flush(true)；返回 bool 持久化结果；对外提供不可变/只读快照并收口写路径到 Update()。
  7. [P1-7] AppLogger 全局静态状态争用（测试必须串行的根因）、高频同步 I/O 阻塞及路径参数拼接风险
    • 源码：src/RemoteBuddy.Core/Diagnostics/AppLogger.cs（L22–61、L113–133、L160–209、L262–291）
    • 根因与影响：全进程可变静态字段在并发测试下相互覆写；_isInitialized/_isEnabled/MinimumLevel/_logFilePath 在锁外无 volatile 读写；每条日志在锁内开关 OS 文件句柄（File.AppendAllText），在实时杀软扫描下易阻塞音频/BLE 线程；OpenLogFolder() 用字符串引号拼接命令参数存在转义/注入隐患。
    • 修复方案：拆分为可实例化 FileLogger（解除测试串行依赖），采用 Channel<string> 后台单消费者 + 持久 StreamWriter 异步落盘，OpenLogFolder 改用 ProcessStartInfo.ArgumentList.Add(dir)。
  8. [P1-8] IBluetoothManager 空实现默认事件 AudioOutputFailed 静默吞订阅，且扫描方法签名重复
    • 源码：src/RemoteBuddy.Core/Bluetooth/IBluetoothManager.cs（L45、L47–51）
    • 根因与影响：AudioOutputFailed 的 { add { } remove { } } 空体导致实现类漏实现时无编译警告，UI 订阅被静默丢弃；StartScanning/StopScanning 与 StartScan/StopScan 并存增加实现歧义。
    • 修复方案：移除事件默认空实现，合并冗余扫描方法。

详细审查发现

P0 — 严重缺陷

  1. [P0-3] 提权外部命令存在 PowerShell 参数注入风险及重定向管道死锁隐患
    • 源码：src/RemoteBuddy.Platform.Windows/Bluetooth/BluetoothAdapterHelper.cs（TryRestartAdapterPnpAsync L187–209、RunCommandAsync L213–241）
    • 根因与影响：
    • 将注册表/PnP 查询获取的设备实例 id 未经白名单校验或转义，直接拼入双层引号嵌套的 PowerShell 命令并在管理员权限（Verb = "runas"）下执行；pnputil.exe 参数拼接同样无引号校验。若 id 含 ', ", $(), ` `` 将触发提权命令注入。
    • RunCommandAsync 在 isAdmin == true 时开启 RedirectStandardOutput/Error = true 后直接 await proc.WaitForExitAsync()，未并发异步消费管道流，子进程输出超过管道缓冲（4KB）即发生永久死锁。
    • 修复方案：对 id 做严格正则白名单校验（^[A-Za-z0-9\\_&-]+$）并改用 PowerShell -EncodedCommand；RunCommandAsync 中在 WaitForExitAsync 前并发 ReadToEndAsync 并加超时（15 秒），或直接关闭流重定向。
  2. [P0-4] WinRtBluetoothManager.Dispose() 超时后无锁销毁 _audioPlayer 引发并发 Use-After-Dispose
    • 源码：src/RemoteBuddy.Platform.Windows/Bluetooth/WinRtBluetoothManager.cs（Dispose / ProcessAudioChannelAsync，L2204–2213）
    • 根因与影响：Dispose() 仅等待 _audioWorkerTask.Wait(250)，超时后不持 _audioLock 直接调用 _audioPlayer.Dispose()。而 DrainAsync 最长可达 450ms+45ms，超过 250ms 时会在后台线程仍使用 _audioPlayer 期间销毁对象，触发 ObjectDisposedException 或 WASAPI 竞态异常，并在 UI 线程造成 250ms 同步阻塞。
    • 修复方案：引入类级 _disposeCts 立即取消 ProcessAudioChannelAsync 与 DrainAsync，通过 lock (_audioLock) 串行化后再释放 _audioPlayer，并在 WriteSamples 锁内校验 _disposed。

覆盖范围：src/RemoteBuddy.Platform.Windows/Input/ 全部 10 个文件（NativeInputSender.cs、RawInputReceiver.cs、RemoteVoiceKeyGuard.cs、HidDeviceReader.cs、DoubaoUsbKeyboard.cs、BthPortRegistryHelper.cs、ChromecastButtonReceiver.cs、ChromecastEtwReceiver.cs、ChromecastWorkerClient.cs、ChromecastWorkerHost.cs），全部已逐行源码审查。

  • 防 SendInput 回环与多设备状态隔离：RawInputReceiver.cs 显式丢弃 hDevice == IntPtr.Zero 合成事件，通过 DEVPKEY_Device_ContainerId 归属设备并按 (hDevice, reportId) 维护按键状态。
  • 提权分离与无阻塞 ETW 转发：ChromecastButtonReceiver.cs、ChromecastWorkerClient.cs 与 ChromecastWorkerHost.cs 将 ETW 提权限制在独立子进程，主进程保持 Medium 完整性；ChromecastEtwReceiver.cs 使用确定性会话名 RemoteBuddy_BthEtw_S{SessionId} 并在 ERROR_ALREADY_EXISTS (183) 时自动回收旧会话。

详细审查发现

P0 — 严重缺陷

  1. [P0-5] 低级键盘钩子漏判 LLKHF_INJECTED，导致软件自身注入的 F5 事件被静默吞掉并提前解除防护
    • 源码：src/RemoteBuddy.Platform.Windows/Input/RemoteVoiceKeyGuard.cs（OnKeyboard、Arm）
    • 根因与影响：当事件为注入事件（(flags & 0x10) != 0）时，仅跳过了 _ownsF5 分支而未立即放行，直接落入后方 if (sessionActive || _armed) 分支并返回 (IntPtr)1 吞掉事件。导致 Arm() 补发的清理 F5 KeyUp 被自己拦截且立即清除 _armed；语音激活期间注入含 F5 的目标快捷键（如微信 Ctrl+F5）也会被自身钩子吞掉。
    • 修复方案：检测到 (flags & 0x10) != 0 后立即 return CallNextHookEx(_hook, code, message, data);（可结合 dwExtraInfo == NativeInputSender.SyntheticEventMarker 进一步精确放行）。
  2. [P0-6] ChromecastEtwReceiver.Stop() 在消费线程退出前释放非托管缓冲区与委托，存在 Use-After-Free 崩溃风险
    • 源码：src/RemoteBuddy.Platform.Windows/Input/ChromecastEtwReceiver.cs（Stop L1008–1044、CleanupUnmanaged L1046–1063）
    • 根因与影响：Stop() 在 lock (_lock) 内调用 CloseTrace/ControlTraceW 后立刻执行 CleanupUnmanaged() 释放 LoggerName/_logfileBuffer/_propertiesBuffer 并置空 _callbackHolder，随后才在锁外 _processThread.Join(500)。若 ProcessTrace 正在排空残留缓冲或回调 ProcessEventRecord，将触发原生堆 UAF（AccessViolationException）。
    • 修复方案：先在锁内停止会话并取出 _processThread，在锁外 Join(3000) 确认线程完全退出后，再执行 CleanupUnmanaged()。

P1 — 高危隐患

  1. [P1-14] 命名管道缺少客户端 PID 校验且命令行明文暴露管道名，UAC 窗口期存在本地抢连与伪造按键注入风险
    • 源码：src/RemoteBuddy.Platform.Windows/Input/ChromecastWorkerClient.cs（StartAsync，L72–141）
    • 根因与影响：管道名经命令行明文传参（--chromecast-worker {pipeName}），ACL 同时赋予当前用户（为空时甚至退化为 BuiltinUsersSid）与管理员 ReadWrite，且连接建立后未校验对端 PID 是否等于 workerProcess.Id。同用户低权限恶意进程可在 UAC 弹窗数秒内抢先连入管道并伪造 MsgTypeButtonEvent 触发快捷键或语音录制。
    • 修复方案：连接后立即调用 GetNamedPipeClientProcessId 校验 clientPid == (uint)workerProcess.Id；移除 BuiltinUsersSid 兜底。
  2. [P1-15] NativeInputSender 存在单键卡键漏追踪、Unicode 部分发送无法回滚及 UIPI 静默失败无感知
    • 源码：src/RemoteBuddy.Platform.Windows/Input/NativeInputSender.cs（SendKey、SendShortcutDown、BuildUnclosedReleaseInputs、SendUnicodeText）
    • 根因与影响：SendKey 未对称维护 _heldSyntheticKeys，异常断连时无法自动释放；BuildUnclosedReleaseInputs 跳过 vk == 0 导致 KEYEVENTF_UNICODE 半途失败无法补发 KeyUp；SendShortcutDown 部分失败时调用 ReleaseAllHeldSyntheticKeys() 会误清其他无关持键；从未在 sent < inputs.Length 时读取 Marshal.GetLastWin32Error()，导致前台为管理员窗口时 UIPI 拦截（ERROR_ACCESS_DENIED = 5）完全无诊断提示。
    • 修复方案：SendKey 对称追踪持键；Unicode 按 wScan 配对回滚；部分失败仅释放本次已发子集；记录 Win32 错误码并在 UIPI 拦截时向上层告警。
  3. [P1-16] DoubaoUsbKeyboard 完全无线程同步、finally 未保护删除掩盖异常且缺乏驱动检查与回环绑定验证
    • 源码：src/RemoteBuddy.Platform.Windows/Input/DoubaoUsbKeyboard.cs（L16–100、L142–162）
    • 根因与影响：_context/_keyboard/_keysHeld 无锁保护且无 _disposed 位，并发 SendClick（含 Thread.Sleep(45)）与 Dispose() 可重建泄漏句柄或导致卡键；EnsureKeyboard() 的 finally 直接执行非递归 Directory.Delete 且无 try/catch，会覆盖真实异常；未检查 USB/IP 驱动状态与失败熔断，也未在代码层验证 HMBackend.Usbip 仅绑定 127.0.0.1。
    • 修复方案：增加 _sync 锁与 _disposed 标志；finally 清理独立 try/catch + 递归删除；增加驱动前置检查/失败冷却，并审计 HIDMaestro 的 USB/IP 绑定地址。
  4. [P1-17] HidDeviceReader.Stop() 与断连退出未释放已按下按键，且存在 SafeFileHandle 并发释放竞态
    • 源码：src/RemoteBuddy.Platform.Windows/Input/HidDeviceReader.cs（Start L233–269、ReadLoopAsync L283–326、Stop L360–374）
    • 根因与影响：Stop() 与断连退出仅清空 _pressedButtons 而不派发 ButtonEvent(btn, false)，导致下游组合键卡死；Start/Stop 无互斥锁且直接 Dispose() _handle 与 ReadLoopAsync 竞争。
    • 修复方案：取出快照后在锁外逐一派发 KeyUp；同步化启停生命周期，先取消 CancellationToken 并短暂等待 _readTask 结束后再释放 _handle。
  5. [P1-18] 提权 Worker 300ms 强杀超时与缺少进程退出钩子，易致系统全局 ETW Session 泄漏
    • 源码：src/RemoteBuddy.Platform.Windows/Input/ChromecastWorkerClient.cs（DisposeResources L302–327）、src/RemoteBuddy.Platform.Windows/Input/ChromecastWorkerHost.cs（RunWorkerAsync L154–162）
    • 根因与影响：Client 仅等 300ms 即 Kill(entireProcessTree: true)，而 Host 优雅停止需最长 ~1000ms；Host 未注册 ProcessExit / SetConsoleCtrlHandler。Windows 全局 ETW 会话上限约 64 个，强杀会遗留内核会话常驻至重启。
    • 修复方案：将等待超时提高至 ≥2000ms；在 Host 注册退出钩子尽力调用 receiver.Stop()。
  6. [P1-19] RawInputReceiver 在锁内逐包分配 RIDI_PREPARSEDDATA 拖慢 UI 线程，且静态 _containerIdCache 负缓存可破坏多设备隔离
    • 源码：src/RemoteBuddy.Platform.Windows/Input/RawInputReceiver.cs（L125–138、L214–249、L441–468）
    • 根因与影响：UI 线程 WndProc 持锁期间每帧执行两次 GetRawInputDeviceInfo + 非托管堆分配，增加 WH_KEYBOARD_LL 触碰 LowLevelHooksTimeout 被系统摘除的风险；GetDeviceContainerId 永久缓存 null 导致退化到仅按大厂 VID（VID_18D1/VID_2717）匹配的 IsKnownRemoteDevice，可能误接管同厂商蓝牙键盘/鼠标。
    • 修复方案：按 hDevice 缓存 PreparsedData 并将 P/Invoke 移出锁；不永久缓存 null ContainerId（设 3–5 秒 TTL）；大厂 VID 强制同时校验遥控器 PID（9450/32B8）。

  5. [P1-24] GeneralViewModel 事件订阅未退订（内存泄漏）+ 构造期误触发注册表与磁盘双写
    • 源码：SubViewModels.cs（GeneralViewModel / SettingsViewModel 构造函数）
    • 根因与影响：匿名 Lambda 订阅 _bt.ConnectionStatusChanged 无 IDisposable 退订；构造函数对属性（而非私有字段）赋值触发 OnXxxChanged，每次启动同步执行 2 次注册表写入 + 2~4 次配置落盘。
    • 修复方案：构造期直接赋 backing field；实现 IDisposable 并在 MainViewModel.Dispose() 退订。
  6. [P1-25] MainViewModel（646 行）God Object、_etwSources 跨线程竞态与无保护火发任务
    • 源码：MainViewModel.cs（RefreshInputSources、StartProbeRetryLoop、HandleDeviceButton）
    • 根因与影响：UI 状态与全部硬件编排耦合，被迫暴露多个 *ForTest 后门；_etwSources 锁外写锁内读存在数据竞争；多处 _ = ...Async(...) 无 try/catch 吞掉即时异常。
    • 修复方案：抽离 RemoteOrchestratorService 承担硬件/输入/语音编排；对 _etwSources 统一加锁或用不可变快照；引入 SafeFireAndForget 统一捕获记录异常。
  7. [P1-26] OnboardingViewModel 异步连接竞态、关闭后悬挂回调及缺少异常捕获
    • 源码：OnboardingViewModel.cs（ConnectDeviceAsync、InstallCableAsync）、SubViewModels.cs
    • 根因与影响：快速点击不同设备连接缺少并发互斥与 _isDisposed/SelectedDevice 校验，慢返回结果覆盖新状态；4 个 async Task 命令缺少 try/catch，异常时界面永久卡在“正在连接”。
    • 修复方案：引入 CancellationTokenSource 与 IsConnecting 互斥状态，await 后校验存活与当前选择，补充 try/catch 展示友好错误。
  8. [P1-27] MappingPage 预览抑制在确认框弹出时失效，且快捷键录制缺少危险键与冲突校验
    • 源码：MainViewModel.cs、VoiceShortcutRecorder.cs、MappingPage.xaml.cs
    • 根因与影响：弹出“恢复默认映射”确认框时 MainWindow.IsActive 变 false，抑制瞬间失效，误按遥控器可向弹窗注入 Enter 误确认重置；录制器未拦截 Alt+F4/Win+L 或无修饰单字符键，也未提示与映射冲突。
    • 修复方案：扩展抑制条件检测任意所属弹窗活动状态；增加高危系统键黑名单、单字符警告与映射冲突检测。

详细审查发现

P0 — 严重缺陷

  1. [P0-9] VB-CABLE 自建镜像分发与法律声明自相矛盾，存在专有软件再分发合规风险
    • 源码/文档：THIRD_PARTY_NOTICES.md（第 4 节）、README.md、VbCableInstaller.cs、VbCableInstallerTests.cs
    • 根因与影响：声明明确称“VB-CABLE 不捆绑、不转授权、不再分发，由用户自行从 VB-Audio 官网下载”，但代码实际优先从项目自有域名 remote.zfdang.com 下载专有包 VBCABLE_Driver_Pack46.zip。VB-CABLE 为专有 Donationware，未经官方书面许可镜像分发构成合规风险且与声明直接冲突。
    • 修复方案：除非已获 VB-Audio 书面镜像授权并在 THIRD_PARTY_NOTICES.md 明示，否则移除自建镜像源，仅直连 VB-Audio 官方下载或引导浏览器打开官网下载。
  2. [P0-10] GPL-3.0-only 与 WPF-UI 4.0.3 内嵌的 microsoft/segoe-fluent-icons-font 许可条款存在法律冲突
    • 源码/文档：THIRD_PARTY_NOTICES.md（第 2 节）、RemoteBuddy.App.csproj、LICENSE
    • 根因与影响：WPF-UI 附带的微软字体条款禁止任何形式的再分发，与 GPL-3.0-only 自包含单文件二进制的自由再分发要求直接冲突。（结合第五章审查：RemoteBuddy.App 全部 XAML 实际零引用 WPF-UI，直接移除该死依赖即可一举消除合规冲突并缩小包体积！）
    • 修复方案：直接从 RemoteBuddy.App.csproj 移除未使用的 WPF-UI 4.0.3 引用，并同步清理 THIRD_PARTY_NOTICES.md 对应条款。
  3. [P0-11] scripts/convert-icon.ps1 硬编码个人本机绝对路径与旧项目名 voice-input-buddy-windows
    • 源码：scripts/convert-icon.ps1（L1–2 及全文）
    • 根因与影响：硬编码 d:\works\remote-buddy\assets 与 d:\works\voice-input-buddy-windows\...，缺 $ErrorActionPreference = "Stop"、路径校验及非托管图像句柄释放，在其他机器完全不可用。
    • 修复方案：改为脚本参数并基于 $PSScriptRoot 推导默认目标路径，补充错误处理与 try/finally 释放。

P1 — 高危隐患

  1. [P1-28] 核心平台模块存在大面积测试覆盖盲区
    • 源码：src/RemoteBuddy.Tests/ 对照 src/RemoteBuddy.Platform.Windows/
    • 根因与影响：WinRtBluetoothManager（GATT 发现/重连/保活）、MultiRemoteBluetoothManager（多设备路由）、WasapiAudioPlayer（设备切换与异常恢复）、DoubaoUsbKeyboard（USB/IP 挂载与降级）以及 ChromecastWorkerHost/Client、BthPortRegistryHelper、StartupService、HidDeviceReader 均接近零实质测试覆盖。
    • 修复方案：优先为 Named Pipe 帧协议、MultiRemoteBluetoothManager 编排与接口抽象后的 DoubaoUsbKeyboard 补齐纯内存单测，并接入 coverlet.collector 输出覆盖率基线。
  2. [P1-29] 全局禁用测试并行化且存在静态全局状态泄漏
    • 源码：AssemblyInfo.cs、ConvertersAndViewModelTests.cs、ChromecastEtwTests.cs
    • 根因与影响：DisableTestParallelization = true 掩盖并发共享状态缺陷；DevicesViewModel.ConfirmDeviceRemovalHandler 未在 try/finally 复位；ChromecastEtwTests 修改了 AppLogger 和 BluetoothAdapterHelper.CustomRestartHandler 却未加入 [Collection("AppLogger")]。
    • 修复方案：所有静态钩子均用 try/finally 复位，归入单一 [Collection("GlobalState")] 后移除全局串行开关（配合第二章重构 AppLogger 为可实例化）。
  3. [P1-30] CI/CD 供应链安全与发布制品完整性缺失
    • 源码：.github/workflows/release.yml（L24、L29、L68、L83、L88–99）
    • 根因与影响：Actions 使用可变主版本标签（@v4）未 SHA-pin；发布包缺少 SHA256SUMS.txt、actions/attest-build-provenance 与 Authenticode 代码签名；每次 push main 以 --clobber 覆盖正式 Release。
    • 修复方案：全量 SHA-pin Actions、随 Release 生成并上传 SHA256SUMS.txt 与构建溯源证明，将正式发布改为 v* Tag 触发或 main 标记 --prerelease。
  4. [P1-31] scripts/release-metadata.sh 存在 Windows tzdata 缺失静默回退、1000 次提交回绕与 SemVer 前导零隐患
    • 源码：scripts/release-metadata.sh（L12–28）
    • 根因与影响：ZoneInfo('Asia/Singapore') 在缺少 tzdata 的 Windows Python 环境中静默回退为当前 UTC 时间，破坏确定性版本号；$((count % 1000)) 在第 1000 次提交回绕冲突；月/日前导零不符合 SemVer 2.0。
    • 修复方案：改用固定 timezone(timedelta(hours=8))、移除 % 1000 取模、去掉月/日前导零。
  5. [P1-32] scripts/build.ps1 自动下载执行远程脚本无校验且 SDK 版本检测有缺陷
    • 源码：scripts/build.ps1（L34–48、L60、L79–87）
    • 根因与影响：仅判断 dotnet --list-sdks 非空（装有 .NET 8/9 即误判通过）；无哈希校验即 -ExecutionPolicy Bypass 执行远程 dotnet-install.ps1；全局强杀 testhost*；残留 RemoteBuddy.App.old.<guid>.exe 从不清理。
    • 修复方案：精确正则校验 ^10\.0\.、移除静默远程脚本执行、清理历史 .old.*.exe 并避免误杀全局 testhost*。
