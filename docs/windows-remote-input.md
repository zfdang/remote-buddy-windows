# Windows 遥控器按键采集、并发与隔离

设备码表和实机报告见 [G9N9N](g9n9n-buttons.md) 与 [小米 RC003](xiaomi-rc003-buttons.md)。

## 普通键与设备身份

1. 应用为每个已配置并连接的遥控器维护独立 BLE／ATVV 连接。启动会尝试重连已保存的遥控器。设备页面可以分别连接或断开设备。映射页面的选择只决定正在编辑哪一份映射。
2. Raw Input 通过蓝牙地址或 Windows Container ID 匹配实体设备，并拒绝没有来源句柄的事件。直接 HID 打开各遥控器自己的接口。主窗口不将缺少设备身份的 `WM_APPCOMMAND` 用作全局映射来源。
3. ETW 使用一个 BthPort HCIRAW Event 402 跟踪会话。通过发给各 BLE 设备的唯一 GATT 查询，应用把 ACL 连接句柄绑定到该设备的地址。必须在同一连接看到查询响应，或在看到唯一出站查询后收到有效按键报告，才接受该连接的按键。解码器由型号决定，设备身份由连接确认，两只同型号遥控器的状态互不相干。
4. 应用按设备维护去重和单击、双击、长按、连发状态。两只同时按相同的键，各自使用自己的映射。一只断开时只取消它挂起的手势。

所有型号的默认长按规则相同。方向键、确认键、音量加减和单击为 Backspace 的电源键可以连发，以该型号实际提供的映射为准。其他键默认没有长按动作，用户仍可单独设置。

## 语音占用

任一已连接遥控器的语音键都可以在麦克风空闲时开麦。应用在开启音频输出之前获取唯一的语音占用权。占用从开麦开始持续到收尾及输入法快捷键释放。其他遥控器的语音按键在这段时间内不会开始新会话，也不能结束当前会话，普通键仍照常可用。当前遥控器断开或开麦失败会释放占用权。其他遥控器可以在空闲后重新按语音键，不会自动接管之前被拒绝的那次按压。

## 诊断与验证

ETW 使用每个 Windows 会话固定的名称 `RemoteBuddy_BthEtw_S<会话 ID>`，下次启动可回收异常退出留下的同名会话。2026-11-23，本机曾出现会话启动成功却始终无 Event 402；清理两个旧进程留下的会话后，历史版和修复版都重新收到事件。

排查时依次检查「收到 Event 402」「观察到设备的 GATT 查询」「设备地址与 ACL 句柄绑定」「收到带地址的按下／松开」。自动化测试覆盖三只设备同时输入，其中两只型号相同，并覆盖语音抢占和断开后的状态隔离。真机验收还应按住一只的语音键时操作另一只的普通键，再在会话结束后用另一只开麦。
